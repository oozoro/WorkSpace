# 実装指示書: 生成GUIにチェックポイント切り替えUIを追加する

**この文書は実装を担当するAI(Claude Code)への指示書である。**
上から順に作業すること。判断に迷ったら勝手に決めず「不明点の扱い」の
節に従うこと。

## ゴール

ユーザーの画像生成GUI(ブラウザで動く自作ダッシュボード)に、
ベースモデル(SDXLチェックポイント)を切り替えるUIを追加する。
ユーザーは5つのチェックポイントを比較評価したいので、
「いま使っているモデルがどれか」が常に見え、クリックだけで
切り替えられることが必須要件。

## Phase 0: コードベース調査(最初にやる。コードはまだ書かない)

1. GUIのプロジェクトフォルダで上記アンカー文字列をgrepし、
   フロントエンドのファイル(html/js/テンプレート)を特定する
2. そのフロントが叩いているHTTPエンドポイント(fetch/axios/WebSocket)を
   列挙し、生成リクエストを処理しているサーバ側コードを特定する
3. サーバ側で**現在チェックポイントをどう読み込んでいるか**を特定する。
   以下のどれかのはず:
   - **A1111/Forge系API使用**: `sdapi/v1/txt2img` などのURLがある
   - **ComfyUI API使用**: `/prompt` へのPOSTや workflow JSON、
     `CheckpointLoaderSimple` / `ckpt_name` という文字列がある
   - **diffusers等の直接ロード**: `from_single_file` / `from_pretrained` /
     `StableDiffusionXLPipeline` などがPythonコードにある
4. 特定結果(どのファイル・どの方式か)を短く報告してから実装に進む

## Phase 1: バックエンドに切り替え機能を追加

共通仕様:
- 新エンドポイント `GET /api/checkpoint` … 現在のモデルidを返す
- 新エンドポイント `POST /api/checkpoint` … `{"id": "janku-v6"}` 形式で
  切り替え。5モデルのid→ファイルパス対応表はサーバ側に定数で持つ
  (既存の設定ファイル方式があるならそれに従う)
- **生成処理の実行中に切り替え要求が来た場合は、実行中ジョブの完了を
  待ってから切り替える**(生成キューが常に回っているGUIなので重要)
- 切り替え完了までフロントに状態を返せるようにする(切替中フラグ)
- 選択は設定ファイル等に永続化し、GUI再起動後も維持する

方式別の実装:
- **A1111/Forge系**: `POST /sdapi/v1/options` に
  `{"sd_model_checkpoint": "<ファイル名>"}` を送る。モデルファイルは
  A1111側の `models/Stable-diffusion/` に置く必要がある —
  `C:\Users\ycwbk\WorkSpace\models\checkpoints\` からのコピーではなく
  シンボリックリンク作成をユーザーに提案する(管理者権限が要る場合は
  `mklink` の手順を提示)
- **ComfyUI系**: 生成時に送っているworkflow JSONの
  `CheckpointLoaderSimple` ノードの `ckpt_name` を選択モデルに
  差し替える。モデルは ComfyUI の `models/checkpoints/` に
  リンク/配置する(extra_model_paths.yaml で
  `C:\Users\ycwbk\WorkSpace\models\checkpoints` を追加する方法を優先)
- **diffusers直**: パイプラインを保持している変数を切替時に破棄して
  `torch.cuda.empty_cache()` 後に新モデルを `from_single_file` で
  ロードし直す。VRAM不足に注意(6.5GB級。旧モデル解放を先に行う)

## Phase 2: フロントエンドにUIを追加

- 既存のボタン列(顔補正ON / NSFW / 健全モード / LoRA)の並びに
  **現在のモデル名を表示するドロップダウン**を1つ追加する
  (例: `🎨 JANKU v6 ▼`)。ボタン5個並べるより省スペースなので
  ドロップダウンを推奨するが、既存UIの部品の作りに合わせること
- 切り替え中は「切替中…」表示にして操作不能にする(連打対策)
- 切り替え完了/失敗はGUI既存の通知方法に合わせて表示する
- 見た目は既存ボタンのCSSクラスを再利用し、新しいデザインを発明しない

## Phase 3: 生成画像へのモデル記録(評価データのため)

このGUIは画像を採用/崩れで評価してLoRA学習に使う仕組みなので、
**どのチェックポイントで生成した画像かを記録に残すこと**:

- 生成画像のメタデータ(既存の生成情報保存の仕組み)に
  チェックポイントidを追加する
- 既存DBやJSONに生成パラメータを保存している箇所があれば、
  そこに `checkpoint` フィールドを足す
- 評価一覧の画面改修までは不要(データに残っていればよい)

## 任意(余裕があれば): 推奨設定の自動適用

前提情報の表に推奨sampler/steps/CFGがあるモデルに切り替えたとき、
生成設定をそれに合わせるかをユーザーに確認するトグル
(「推奨設定を使う」チェックボックス)を追加してもよい。
デフォルトはOFF(現在の設定を勝手に変えない)。

## してはいけないこと

- 既存の生成ループ・評価機能・LoRA学習まわりのリファクタリング
- 依存ライブラリの追加(既にあるものだけで作る)
- モデルファイルの移動やリネーム(リンク作成はよい)
- 5モデル以外のモデルの自動検出などのスコープ拡大

## 動作確認手順(実装後に必ず実施)

1. GUIを起動し、ドロップダウンに5モデルが出て現在値が表示される
2. 生成が動いていない状態で切り替え → 完了表示が出て、次の生成が
   新モデルで行われる(生成情報のメタデータで確認)
3. 生成中に切り替え → 実行中の1枚は旧モデルで完走し、その後に切替わる
4. GUIを再起動 → 選択したモデルが維持されている
5. 存在しないid をPOST → エラーになるがGUIは壊れない
